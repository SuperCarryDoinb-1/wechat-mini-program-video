# wechat-mini-program-video

给微信小程序 / App / Web 产品做**产品介绍片**的实战 skill：一套流程 + 一份踩坑清单。

不是教程，是把一支真实产品片（34 秒、1080×1920、真实界面 + 抖音式翻页 + 海报结尾）从零做完之后，复盘出来的可复用做法。

## 它解决什么

用真实产品界面做视频时，每次都会重新踩的几类坑：

- **素材保真**：截图带 iframe 边框、内容比视口高被裁、缩放后四周露白边
- **动效手势**：抖音式一页一停怎么实现；为什么移动的 UI 元素不能抠图重画
- **版式安全**：内容贴边、文字被平台 UI 盖住
- **音频交付**：24-bit WAV 浏览器放不出、AAC 编码让真峰值超标、CC BY 署名
- **返工沟通**：用户说「信息量太低」「不够高级」时该怎么处理

## 怎么用

这是一个 skill 文件，主要给支持 skills 的 AI 编码助手（Claude Code / Codex / Cursor 等）读。

- **配合 [motion-showreel](https://github.com/) 使用**：`motion-showreel` 管「怎么把片子做出来」（页面契约、确定性渲染、审片、导出），本 skill 管「做产品介绍片这一类片子的具体做法和坑」。
- 单独读也成立：里面的判断和参数（上滑时长、底部留白、按页适配公式、真峰值处理）跟工具无关。

## 几个最值钱的结论

1. 内容比视口高时，**改截图，不要后期缩放**——缺失的像素补不回来
2. 移动的 UI 元素**从每页原图取**，不要抠图重画——抠出来会带旧进度条，抠干净会断成两截
3. 卡片底色用**页面的本色**，不要用白色——否则缩放后四周露白边
4. 停留时必须有动，否则验收直接判「死帧」
5. AAC 编码会抬高真峰值，母带合格不代表成片合格，导出后必须重封一次
6. 用户说「不高级」，多半是整屏只有一处在动，而不是特效不够
7. 审美分歧不要用文字描述，做成 9:16 小样让用户点选

## 边界

- 不替代 `motion-showreel` 的制作规范与验收标准
- 只覆盖「产品介绍片」这一类：素材怎么来、翻页怎么做、音乐怎么合法、验收额外看什么
- 不包含任何真实产品的截图与素材（那些属于各自的产品）
